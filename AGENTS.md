# AGENTS.md

The agent-facing operating guide for this repository. `README.md` is the
human-facing quickstart and intentionally omits implementation detail; this file
is authoritative for agents. Update it whenever commands, invariants, or
cross-platform contracts change.

## Products and layout

| Product | Location | Identifiers |
|---|---|---|
| Core library | `crates/filmlogger-rs` | Rust package `filmlogger-rs`, lib `filmlogger_rs` |
| Desktop app | `apps/desktop` | Tauri 2 shell `src-tauri`, package `filmlogger-rs-desktop`, lib `filmlogger_rs_desktop`; UI `ui` is plain TypeScript + Vite + vitest |
| Android app | `apps/android` | Kotlin/Compose app `app`, package `ca.jakelandau.filmlogger`; uniffi bridge `rust`, package `filmlogger-rs-ffi`, lib `filmlogger_rs_ffi` |

Workspace facts: resolver 3, Rust edition 2024, MSRV 1.85, license
AGPL-3.0-or-later, workspace lints `unsafe_code = "warn"` and
`clippy::pedantic = "warn"`.

Android toolchain facts: AGP 8.10.1, Kotlin 2.0.21, Gradle 8.11.1, compileSdk
37, minSdk 26, JDK 21 (Gradle JVM via `gradle.properties`, compiler target JVM
17), arm64-v8a only, uniffi 0.32. CI uses Node 22.

Native storage: desktop opens `<app_config_dir>/watch_log.db`; Android opens
`<filesDir>/film_logger.db`. Both use the same schema version, and these
filenames are stable user data.

Release runbook: `docs/RELEASING.md`.

## Where behavior lives

Core library (`crates/filmlogger-rs/src`):

- `domain.rs` — IDs, formats, legality, validation, serde.
- `catalog.rs` — `format_catalog()`, shared by both UIs.
- `store.rs` — schema/migrations, derived projections, stats, import/export.
- `service.rs` — `FilmLogger` facade.
- `tmdb.rs` — blocking TMDB client.
- `error.rs` — `thiserror` variants.

Desktop bridge: `apps/desktop/src-tauri/src/lib.rs` holds the Tauri commands,
`run_blocking`, and app bootstrap; `src/contract_tests.rs` checks the command
list against `generate_handler!` and `api.ts`; `ui/src/api.ts` is the sole IPC
wrapper; `ui/src/types.ts` mirrors the Rust serde shapes; `ui/src/stats-time.ts`
computes the weekday/hour buckets.

Android bridge: `apps/android/rust/src/{lib,types,convert}.rs` hold the uniffi
surface, DTOs, and conversions; screens live in
`app/src/main/kotlin/ca/jakelandau/filmlogger/ui`; the generated bindings are
written to `app/src/main/kotlin/uniffi/filmlogger_rs_ffi` (gitignored build
output, regenerated by the `generateKotlin` Gradle task).

Apps call the `FilmLogger` facade. `Store` is public mainly for tests and tools;
it is not a second app-facing API.

## Non-negotiable invariants

1. The Rust core is the source of truth for the domain model, format legality,
   validation, persistence, aggregate statistics, and TMDB access. Do not
   reimplement those rules in TypeScript or Kotlin. Presentation-only filtering
   and sorting may live in the UI, but must match across platforms.
2. Desktop and Android parity: the same content, actions, strings, and computed
   values on every screen; only native chrome, widget type, and layout differ.
   Any user-visible change updates both platforms and both test suites.
3. Exception to (1): weekday and hour-of-day stats are computed client-side in
   each log's own time zone because the core aggregates the other dimensions in
   UTC. `apps/desktop/ui/src/stats-time.ts` and
   `apps/android/app/src/main/kotlin/ca/jakelandau/filmlogger/ui/StatsTime.kt`
   implement the same contract: Monday-first weekdays, `HH:00` hour labels,
   empty buckets omitted, unknown time zone falls back to the device zone, and
   invalid or missing timestamps are skipped. Change both implementations plus
   `stats-time.test.ts` and `StatsTimeTest.kt`.
4. Every watch log has a valid format. `WatchLog::validate()` requires a format
   and a matching venue; `Format::validate()` enforces projection/screen/flag
   and home-medium/flag legality (`ProjectionScreenMismatch`, `FlagMismatch`,
   `HomeFlagMismatch`, `VenueFormatMismatch`, `MissingFormat`). Never bypass
   validation, default a missing format, or hand-write store rows.
5. Film identity: `FilmId::Imdb` when TMDB supplies an IMDB id, otherwise
   `FilmId::Tmdb`; the canonical key is `tt…` or `tmdb:<n>` via `FilmId::key()`,
   parsed with `FilmId::from_key()`. Tauri commands and the desktop UI cross the
   boundary using that key string; the uniffi DTO mirrors `FilmId` as an enum
   (`Imdb { id }` / `Tmdb { id }`), and the FFI crate exports
   `film_id_from_key` / `film_key_of` (Kotlin `filmIdFromKey` / `filmKeyOf`) so
   neither client parses or formats the key itself. Never use a raw TMDB id as
   the canonical key when an IMDB id exists.
6. Time: `watched_at` is stored in UTC. Constructors take device-local wall time
   (`DateTime<Local>`) and convert; `NewLogDetails.watched_at` is UTC;
   `timezone` stores the IANA zone the time was entered in. Display uses the log
   zone with device fallback. Core year/month stats are UTC; weekday/hour are
   zone-aware in the clients.
7. Store-derived fields: `rewatch` (true when the viewing is not the film's
   first by `watched_at`, then row id), `watch_count` (all viewings including
   this one), and `format_summary` are maintained by `Store::insert`,
   `Store::update`, and `Store::hydrate`. Supplied values are ignored; clients
   treat them as read-only.
8. User state is separate from TMDB metadata: `favorite`, `watchlisted`, and
   `created_at` are preserved by `upsert_film`; `refresh_film` preserves the
   existing canonical `FilmId` so logs stay attached. Change user state only
   through `set_favorite` / `set_watchlisted`.
9. Schema discipline: `SCHEMA_VERSION` is currently 3 in `store.rs`. Any schema
   change bumps it, adds a migration arm for every prior version, and adds a
   migration test using a versioned fixture in `tests/store.rs` (v1 and v2
   migrations are already covered). Never edit a shipped migration.
   `Store::open` rejects newer schemas with `SchemaTooNew`. Export uses SQLite's
   backup API; import validates `user_version` (1 through current) and
   `PRAGMA integrity_check` before replacing live data; both reject the live
   database path. Do not replace these with file copies, and do not remove the
   `#[serde(default)]` compatibility fields from stored JSON documents.
10. TMDB credentials are compile-time only: `build.rs` reads `TMDB_API_KEY`,
    re-emits it with `cargo:rustc-env`, and
    `COMPILED_API_KEY = option_env!("TMDB_API_KEY")` embeds it. A key starting
    with `eyJ` (v4 Read Access Token) is sent as `Bearer`; anything else is sent
    as `?api_key=`. A missing key yields `NoCompiledApiKey` at
    `FilmLogger::open`. Never read the key from the runtime environment, print
    it, or commit it. Tests use wiremock and `TmdbClient::with_base_url`; only
    the live smoke hits `api.themoviedb.org`.
11. The TMDB client is blocking `reqwest`, and SQLite calls are synchronous.
    Every desktop command runs its work on Tauri's blocking pool through
    `run_blocking` (`run_blocking_mut` for the `&mut` import); a non-`async`
    command would run on the main thread and freeze the webview. Android calls
    use `withContext(Dispatchers.IO)`. Never call these from a UI or main
    thread.
12. Wire contract: the Rust serde shapes are the source of truth.
    `ui/src/types.ts` mirrors them exactly (struct fields stay snake_case);
    `ui/src/api.ts` uses camelCase command argument names because Tauri maps
    them to Rust snake_case parameters. Android FFI DTOs live in
    `rust/src/types.rs` with conversions in `convert.rs`. Adding, removing, or
    renaming a field visible over IPC/FFI requires updating Rust, the TypeScript
    types/UI/tests, the FFI DTOs/conversions, Android usage/tests, and the
    regenerated bindings. Unit enum variants serialize as strings;
    `Custom(String)` serializes as `{"custom": "..."}`. `FilmListEntry.film` is
    the slim `LibraryFilm` projection (the eight fields the Films tab and
    collection cards render); `FilmMetadata` is the full metadata path used by
    a film page. The FFI crate also owns the format-key mapping
    (`format_parts` / `format_from_parts`) that the Android picker drives, so
    Kotlin never hard-codes a catalog key.
13. Generated Android bindings are build output, not source:
    `apps/android/app/src/main/kotlin/uniffi/` is gitignored and produced by the
    `generateKotlin` Gradle task (host debug cdylib plus the `bindgen` example),
    which every Kotlin compile depends on. Never hand-edit the generated file
    and never commit it; regenerate after any FFI surface change, and delete the
    old package directory when the uniffi namespace changes. A new Tauri command
    must be registered in `generate_handler!` and wrapped in `api.ts`; a new FFI
    method must be exported in `lib.rs` and imported from
    `uniffi.filmlogger_rs_ffi` in Kotlin. Kotlin imports reference the
    `filmlogger_rs_ffi` native library name, so the crate's `[lib] name` and the
    `--crate` argument in `app/build.gradle.kts` must stay in step.
14. Rating boards: `RATING_BOARDS` / `rating_boards()` in `domain.rs` is the
    shared list; `Settings.selected_board` stores a region code (default `US`),
    and legacy `mpa` / `bbfc` / `fsk` keys normalize through
    `normalize_board_key`. Do not hard-code board lists in either client.
    Official certification symbols are duplicated for both apps: Android assets
    in `app/src/main/assets/cert-icons/{official,flags}` plus `OfficialIcons.kt`,
    desktop assets in `ui/public/cert-icons/{official,flags}` plus
    `official-icons.ts`; add or change a symbol in both trees and both maps.
15. License: AGPL-3.0-or-later. New dependencies must be AGPL-compatible and
    recorded in `THIRD_PARTY.md`.

## Commands and verification

| Task | Command | Working directory |
|---|---|---|
| Rust tests | `cargo test --workspace` | repo root |
| Rust lint | `cargo clippy --workspace --all-targets -- -D warnings` | repo root |
| Rust format | `cargo fmt --all -- --check` | repo root |
| Desktop UI install | `npm ci` | `apps/desktop/ui` |
| Desktop UI type-check | `npm run check` | `apps/desktop/ui` |
| Desktop UI tests | `npm test` | `apps/desktop/ui` |
| Desktop UI build | `npm run build` | `apps/desktop/ui` |
| Desktop shell (release) | `cargo build --release -p filmlogger-rs-desktop` | repo root, after the UI build |
| Android tests + debug APK | `bash ./gradlew testDebugUnitTest assembleDebug -PtmdbApiKey="$TMDB_API_KEY" -PcargoBin="$(command -v cargo)" -PndkRoot="$ANDROID_NDK_HOME"` | `apps/android` |
| Live TMDB smoke | `cargo run -p filmlogger-rs --example tmdb_smoke` | repo root |
| Regenerate bindings | `bash ./gradlew generateKotlin -PcargoBin="$(command -v cargo)"` | `apps/android` |

Manual binding-generation fallback (repo root), when Gradle cannot run:

```sh
cargo build -p filmlogger-rs-ffi
cargo run -p filmlogger-rs-ffi --example bindgen -- generate \
  -l kotlin --crate filmlogger_rs_ffi \
  --out-dir apps/android/app/src/main/kotlin \
  target/debug/filmlogger_rs_ffi.dll
```

Use `target/debug/libfilmlogger_rs_ffi.so` on Linux or `.dylib` on macOS.

Notes:

- `cargo test` needs no TMDB key; only the live smoke does. The key is embedded
  at compile time, so changing it requires a rebuild (`rerun-if-env-changed`).
- PowerShell: `$env:TMDB_API_KEY = "..."`; bash/zsh: `export TMDB_API_KEY="..."`.
- Android Gradle daemons hide the shell environment, so the key must be passed
  as `-PtmdbApiKey`. An empty value builds a keyless cdylib that fails at
  `Logger.open` with `NoCompiledApiKey`.
- `gradlew` is committed without the execute bit (added from Windows); always
  invoke it as `bash ./gradlew`. CI passes
  `-Dorg.gradle.java.home="$JAVA_HOME"`; locally `gradle.properties` pins JDK 21.
- On Windows workstations where `bash` resolves to WSL (no JDK inside, and
  environment variables do not cross into WSL), run the wrapper through
  `cmd /c "gradlew.bat <tasks> -PcargoBin=... -PndkRoot=..."` with `JAVA_HOME`
  set to the JDK 21 install.
- Set `ANDROID_NDK_HOME` / `ANDROID_NDK_LATEST_HOME` or pass `-PndkRoot`; the
  build script's default NDK path is machine-specific. The bridge builds a host
  debug cdylib for bindgen and a release `aarch64-linux-android` cdylib for the
  app.
- `npm ci` requires the committed `package-lock.json`. The `ui` job builds
  `ui/dist` and uploads it for the desktop rows; plain `cargo build` does not
  run Tauri's `beforeBuildCommand`, while `tauri build` (release) does, so the
  release does not pre-build the UI separately.
- `apps/desktop/src-tauri/src/contract_tests.rs` parses `lib.rs` and
  `ui/src/api.ts` and fails when a command is missing from
  `generate_handler!` or `api.ts` (or vice versa). It requires every `api.ts`
  wrapper to keep the one-line `invoke<T>("name", ...)` shape.
- CI (`.github/workflows/ci.yml`) runs Rust tests/clippy/fmt on Windows x64,
  Windows ARM64, Linux x64, Linux ARM64, and macOS; a secret-gated live smoke
  inside the Linux x64 test row; the desktop UI checks once; a release-mode
  desktop shell on every platform and architecture; and Android unit tests plus
  a debug APK. The ARM64 legs use GitHub's hosted `windows-11-arm` and
  `ubuntu-24.04-arm` runners, so they build natively rather than
  cross-compiling. Formatting runs once (it is platform-independent), clippy
  runs on Linux x64 and Windows x64 (it only sees workspace crates), and the
  `ui` job uploads `ui/dist` for the desktop rows instead of each row rebuilding
  it. The live-smoke gate must stay on the step, not the job, because `env` is
  unavailable in a job-level `if`.

### Testing conventions

Core unit tests live beside their modules; integration tests in
`crates/filmlogger-rs/tests` use wiremock, tempfile, and
`Store::open_in_memory`. Desktop pure logic is tested with vitest in
`ui/src/*.test.ts`. Android pure logic is tested with JUnit 4 in
`app/src/test/kotlin`. Do not add live-network tests.

## Conventions and guardrails

Rust: public APIs get `///` docs, fallible public functions get `# Errors`,
expected failures return `Result` (add `thiserror` variants in `error.rs`), and
panics are reserved for impossible states. Keep `clippy::pedantic` clean; do not
silence lints without a narrow reason. Do not add `unsafe` code.

Keep domain serde shapes backward-compatible; additive fields use
`#[serde(default)]`. Renaming or removing a serialized field or enum tag
requires updating both clients and handling existing stored documents.

TypeScript: strict type-check; framework-free DOM code; keep pure logic in
separate modules with vitest coverage; route all IPC through `api.ts`.

Kotlin: Compose Material3; keep pure logic in testable top-level functions;
route all Rust calls through `Dispatchers.IO`; keep desktop and Android copy
identical.

Changelog: record notable user-visible changes under `## [Unreleased]` using
Keep a Changelog categories (`Added`, `Changed`, `Removed`, `Fixed`); do not
rewrite released sections.

Commits: follow the observed Conventional Commits style (`feat:`, `fix:`,
`refactor:`, `test:`, `style:`, `ci:`, `chore:` with optional scope); keep
mechanical renames separate from behavior changes.

Never commit secrets, keystores, signing properties, `.env`, or database files.
`.gitignore` covers them; local signing material lives outside the repo in
`~/.filmlogger/`.

Releases: never push a tag or create a release from an agent. Tags matching
`v*` trigger `.github/workflows/release.yml` (Windows NSIS for x86_64 and
aarch64, Linux AppImage for x86_64 and aarch64, signed Android APK, Tauri
updater metadata). The desktop matrix runs sequentially so tauri-action merges
each platform into `latest.json`, yielding `windows-x86_64`,
`windows-aarch64`, `linux-x86_64`, and `linux-aarch64`. macOS is CI-built but
not published until notarization credentials exist. Versions are set by the
workflow from the tag; Android uses the Actions run number as `versionCode`.

Updaters: desktop reads
`https://github.com/jakelandau/filmlogger-rs/releases/latest/download/latest.json`
from `tauri.conf.json`; Android reads the GitHub latest-release API from
`Updater.kt` (`REPO = "jakelandau/filmlogger-rs"`). A repository rename or a
release-asset rename requires updating both, plus the Android APK selection in
`UpdateLogic.kt`.

Local signing and secret details belong in `docs/RELEASING.md`; do not duplicate
secret values here.
